# WFW430 Control Center — Web MVP

واجهة ويب عربية RTL مبنية من مصنف `WFW430_Control_Center.xlsx` لتشغيل ومتابعة المعرض.

## الوحدات
- لوحة تحكم حسب التاريخ.
- المتابعة اليومية للموظفين.
- محلل CACO لملفات XLSX/XLS/CSV/TSV مع تحقق الإجمالي وتصنيف العمليات.
- سجل الحالات والأخطاء مع تصنيف السبب.
- قاعدة المعرفة قبل التصعيد للمشرف أو 777.
- مرجع العروض.
- إغلاق الشفت وحساب الفرق تلقائيًا.
- دليل الموظفين.
- إعدادات حدود الأخطاء والأوزان.
- تصدير التقارير بصيغة PDF ونسخة احتياطية JSON.
- PWA بسيطة تعمل Offline بعد أول تحميل.

## CACO Analyzer

- يفصل قراءة الملف عن محرك تصنيف قواعد الأعمال.
- يعرض Transaction Type وLine Type وProduct Family وPlan وSIM Type وAttributes كلًا في حقل مستقل.
- يستبعد Total/Subtotal من عد العمليات ويستخدمه للتحقق الحسابي.
- يفصل Sales/Operations عن Invoice Payments، ويحافظ على الأنماط غير المعروفة للمراجعة.
- لا يدمج السجلات تلقائيًا بسبب تكرار MSISDN أو قرب الوقت.
- تكامل Daily Tracking يضيف ملخصات جديدة فقط، وتكامل Shift Closing يعبئ النموذج للمراجعة ولا يحفظه تلقائيًا.
- التحليل مؤقت ولا يغيّر شكل بيانات localStorage؛ يبقى schemaVersion الحالي كما هو.

قواعد CACO المعتمدة موثقة في PROJECT_RULES.md. الاختبارات:

    npm test
    npm run check

## التشغيل محليًا
أي خادم ملفات ثابت يكفي. مثال:

```bash
python -m http.server 8080
```

ثم افتح `http://localhost:8080`.

## حدود النسخة الحالية
البيانات تحفظ في `localStorage` على نفس الجهاز/المتصفح. هذه النسخة مناسبة كـ MVP وتجربة التشغيل. للاستخدام المتزامن بين الموظفين نحتاج Backend (مثل Supabase/Postgres) مع Authentication وRBAC وسجل تدقيق.

## منطق مطابق للمصنف
- حالة الموظف: مستقر / تنبيه-تدريب / مراجعة عاجلة بناءً على حدود الأخطاء.
- إغلاق الشفت: الفرق = الإجمالي الفعلي − إجمالي النظام.
- صفر = مطابق، |الفرق| <= 1 = فرق بسيط، غير ذلك = مراجعة عاجلة.
- لا توجد درجة أداء نهائية في هذه المرحلة؛ المؤشرات للمراجعة فقط.
